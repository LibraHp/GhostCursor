# GhostCursor

将一个应用窗口共享到网页，让远端访客观看画面，并在你本机的对应共享窗口上显示访客鼠标的位置标记。你可以用全局快捷键开启或关闭指定访客的远程控制；授权后，访客操作你现有的系统鼠标。

Windows 桌面端与访客网页已实现。界面使用 Ant Design，采用 Windows 11 风格的浅色背景、圆角面板和蓝色强调。

0.1.1 新增明确的“开启控制”按钮和原生授权确认，访客可查看控制未开启或被收回的原因；新增手机触摸和触控笔的位置标记。10 项自动测试与打包后程序的桌面/触摸模拟链路验收通过。

## 运行

开发环境需要 **Windows x64、Node.js 22.12+（推荐 24）、.NET 10 SDK**。

```powershell
npm install
npm start
```

`npm start` 会完成类型检查、前端构建、Electron 主进程构建和原生程序发布，再启动桌面端。已经构建过可运行 `npm run start:app`。

打包后的程序自带 Chromium 和 .NET 运行时，使用者无需安装 Node.js 或 .NET。

## 使用流程

1. 你启动 GhostCursor，选择要共享的应用窗口并开启 Web 服务。
2. 将加入链接发给访客，访客通过浏览器打开实时画面。
3. 将共享窗口切到前台。访客在网页画面上移动鼠标，你能在本机对应窗口上看到位置标记；默认只显示位置，不移动你的系统鼠标，也不执行点击。
4. 在“在线访客”中选择一位控制者，再点击“开启控制”。程序会尝试将共享窗口切到前台，并等待 Windows 原生程序确认授权；访客看到“你已获得鼠标控制权限”后即可操作。仅勾选“控制者”不会开启权限。
5. 按 `Ctrl+Alt+F8` 或点击“收回控制”即可撤销；快捷键可在“设置”中修改。若切换失败，请手动切回共享窗口，再按快捷键。
6. 停止共享后，视频、远程输入和加入链接一并失效。

移动端同样可以加入：在视频实际内容区域按下或滑动手指，网页和本机共享窗口会显示彩色触摸圆点；抬起、取消或切到后台时隐藏。默认仅显示位置，开启控制后，单指点按和拖动映射为鼠标左键操作。支持触控笔位置；暂不提供多指手势。

访客显示“观看与位置标记”表示尚未获得操作权限。下方会注明等待开启、控制已收回或被系统阻止的原因；请由主持人重新确认授权。目标应用以管理员权限运行时，普通权限的 GhostCursor 可能无法注入输入，此时会显示具体提示，不会继续显示为正在控制。

## 首版设计

| 项目 | 实现 |
| --- | --- |
| 主持人平台 | Windows 10 2004+ / Windows 11，x64 |
| 访客端 | 支持 WebRTC / Pointer Events 的现代桌面和移动浏览器 |
| 共享范围 | 一个指定应用窗口 |
| 网络 | 优先局域网，公网访问后续支持 |
| 视频传输 | Electron 指定窗口捕获 + Chromium 内置 WebRTC，最高 30 fps |
| 会话与消息 | WebSocket 信令，WebRTC DataChannel 传输鼠标位置及控制消息 |
| 访客位置 | 本机透明悬浮标记，按访客区分颜色和名称；触摸/笔显示圆形标记 |
| 远程控制 | 默认关闭，最多 8 位访客、同时最多一位控制 |
| 全局快捷键 | `Ctrl+Alt+F8`，可在设置中修改 |
| 初期输入 | 鼠标移动、点击、拖动和滚轮 |

访客位置标记是绘制在共享窗口上的可视提示，不具备点击能力。开启控制后，本地和远程操作共用现有的系统鼠标；关闭控制后仍可保留位置显示。

普通网页无法直接在其他应用上绘制悬浮标记、注册系统全局快捷键或注入系统输入，因此主持人需要运行桌面程序。访客只需要浏览器。

## 技术栈

- **Electron + TypeScript**：桌面客户端、指定窗口捕获、全局快捷键和内嵌 Node.js Web 服务。
- **React + Vite**：桌面设置界面和访客网页。
- **WebRTC + WebSocket**：实时视频、鼠标位置及控制消息与信令。
- **C# + .NET 10 + WPF/Win32**：原生辅助进程，负责透明位置标记、窗口坐标、目标验证和系统鼠标输入；通过本机命名管道与 Electron 通信。
- **electron-builder**：打包桌面端和原生辅助程序。

位置标记使用不拦截点击、不抢焦点的透明悬浮层，并随共享窗口移动和缩放。坐标按视频实际内容区域计算，排除黑边；捕获宽高比与窗口不匹配时暂停位置显示和输入，避免错误定位。

## 构建与验证

```powershell
npm run check       # TypeScript 类型检查
npm test            # 坐标、授权、消息校验与 HTTP/WebSocket 集成测试
npm run build       # 生成 dist/web、dist/electron 和 dist/native
npm run test:smoke  # Windows 实机链路验收，需要已构建并安装 Microsoft Edge
npm run pack        # 生成 release/win-unpacked/GhostCursor.exe 及配套文件
npm run dist        # 生成 NSIS 安装包与单文件便携版
```

`release/win-unpacked` 必须保留完整目录，不能只复制其中的 exe。安装包与便携版会包含所需文件。

实机验收使用专用测试窗口和独立浏览器，检查实时视频、原生位置标记、观看权限隔离、真实全局快捷键、点击/滚轮与断线清理。截图及验收结果写入 `artifacts/`。验收期间会打开测试窗口并操作其鼠标，请等待结束后再使用电脑。

自动测试覆盖坐标、授权、消息和服务，以及原生确认、授权取消竞争和触摸消息权限隔离。实机验收包含带边框窗口捕获、明确的授权按钮、快捷键、窗口大小变化、前台切换、按住鼠标时断线清理，并使用 Edge 的真实触摸事件模拟检查移动端。实机移动设备、跨设备局域网、防火墙、多显示器和其他 DPI 组合仍需在对应设备上验证。

## 使用限制

- 当前为局域网版本，尚未配置公网 HTTPS、STUN/TURN 或媒体转发服务器。多位访客各占一条视频连接，建议先从 1–3 位访客开始。
- 默认端口为 `3210`。首次使用可按 Windows 提示允许专用网络访问；选择邀请面板中的局域网地址，对方才能从其他设备访问。本机测试地址 `127.0.0.1` 仅供本机使用。
- 为限定操作范围，目标窗口需处于前台。切走、最小化、遮挡输入落点、画面尺寸不匹配时暂停输入；切走会收回控制，回来后需重新按快捷键授权。
- 首版只支持目标顶层窗口内的鼠标移动、左/中/右键、拖动及纵向滚轮；独立弹窗、菜单、管理员权限窗口、受保护画面和某些游戏可能无法捕获或控制。不自动提升权限。
- 访客标记仅绘制在主持人本机。会尝试从视频捕获中排除悬浮层，具体效果取决于 Windows 与捕获后端；不保证其他访客也能从视频中看到标记。
- 键盘、音频、剪贴板、文件传输、轨迹效果和无人值守访问尚未实现。
- 停止共享后凭据失效；新共享或访客重新连接均不会自动恢复控制权限。
