# WebRTC 固定 UDP 端口映射

「WebRTC · 固定 UDP」适用于能够转发一个网页 TCP 端口和一个媒体 UDP 端口的部署。主持人仍在 Windows 电脑运行 GhostCursor，访客仍使用浏览器。视频和鼠标输入使用 WebRTC，网页及信令使用原有 HTTP/WebSocket 服务，控制权限仍由主持人授予并可通过快捷键撤销。

该模式已加入源码，按用户要求未编译、未运行测试，未做路由器、Lucky 或 FRP 的实网连通验证。原有 0.2.1 安装包不包含这些功能。

## 配置例子

假设 Windows 电脑的局域网地址为 `192.168.1.100`，公网 IPv4 为 `203.0.113.10`。这里的公网地址是文档示例，请替换为实际映射入口的公网 IPv4。

| 用途 | 公网入口 | Windows 电脑上的目标 |
| --- | --- | --- |
| 网页及信令 | TCP 13210 | TCP 3210 |
| 视频及鼠标数据通道 | UDP 45000 | UDP 40000 |

1. 停止共享，进入「设置 → 外网与 FRP」。
2. 选择「WebRTC · 固定 UDP」。
3. 公网邀请地址填 `http://203.0.113.10:13210`。网页可以改用域名及 HTTPS，需同时代理 `/ws`。
4. 媒体映射的公网 IPv4 填 `203.0.113.10`，不带协议和端口。媒体入口与网页入口可以是不同 IP。
5. 本机媒体端口填 `40000`，公网映射端口填 `45000`。
6. 保存设置，完成下方实际转发后重新开启共享，再复制完整公网邀请链接给访客。

本机媒体端口允许 1024–65535，公网媒体端口允许 1–65535，必须使用未被其他程序占用的 UDP 端口。无需修改 Windows 显示设置或重启应用。网络设置只能在停止共享时修改；公网地址或映射端口变化后需更新设置并重新共享。

## 路由器或 Lucky

路由器分别添加上述 TCP 和 UDP 转发，目标设备填 Windows 电脑的局域网 IP。使用 Lucky 时，可将网页经「Web 服务」反向代理，再使用真正的 UDP 端口转发或「STUN 内网穿透 → IPv4-UDP」规则转发媒体端口。

如果使用 Lucky 的 UDP STUN 穿透，GhostCursor 中填写该 UDP 规则实际取得的公网 IPv4 和端口；它们不一定与网页 TCP 的入口一致，也可能变化。这里 Lucky 负责暴露 UDP 端口，GhostCursor 不会自动读取 Lucky 的映射状态。

媒体转发的目标应为 `192.168.1.100:40000`，不要默认填写 `127.0.0.1:40000`：WebRTC 媒体套接字可能绑定实际网卡地址，转发到回环地址未必能收到。Windows 防火墙需允许对应的网页 TCP 与媒体 UDP 入站连接。

## FRP 示例

以下为 `frpc.toml` 中的两个代理段，请替换实际地址和端口；frps 的端口允许范围、安全组和防火墙需允许公网的 TCP 13210、UDP 45000。

```toml
[[proxies]]
name = "ghostcursor-web"
type = "tcp"
localIP = "192.168.1.100"
localPort = 3210
remotePort = 13210

[[proxies]]
name = "ghostcursor-media"
type = "udp"
localIP = "192.168.1.100"
localPort = 40000
remotePort = 45000
```

此时 GhostCursor 的媒体公网 IPv4 应填写 frps 服务器的实际 IPv4。本机媒体端口填 `40000`、公网映射端口填 `45000`。UDP 流量经过 FRP 时仍会使用服务器带宽。

## 行为与限制

- 主持端在建立 WebRTC 前，将 Electron 的 UDP 端口范围固定为指定本机端口，并用 BUNDLE 与 RTCP 复用减少媒体套接字。ICE 中增加映射的公网候选地址，同时保留局域网候选地址；不改写本地 SDP、会话授权或 ICE 凭据。
- 一次最多一位访客，避免多个 PeerConnection 争用同一个固定端口。需要多人观看时可选择 WebSocket 或普通 WebRTC。
- 不使用 STUN 或 TURN 地址，也不下载自动 STUN 列表；原来保存的 STUN/TURN 设置会保留，切回普通 WebRTC 时可继续使用。
- 媒体公网地址目前仅接受 IPv4 字面值，不支持域名或 IPv6。网页地址仍可使用域名和 HTTPS。HTTP 反向代理只能处理网页与信令，不能代替媒体 UDP 转发。
- 不承诺绕过访客网络的 UDP 限制。只有网页成功打开时，媒体端口仍可能不通；连接超时会提示检查公网地址、端口映射和防火墙。无法采集到匹配的 IPv4 UDP 候选时会报告端口或网卡问题。
- 切换回其他模式后，下次共享会恢复不限范围的 WebRTC UDP 端口，不影响原有 WebSocket 和自动 STUN 功能。
